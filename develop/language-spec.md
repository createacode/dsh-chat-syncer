# 插件语言与文案规范

> 适用范围：`client.js` 的界面文案、Host 返回的错误与状态文本、README 与 docs、Git 提交、代码注释和标识符命名。  
> 目标：同一个功能在所有入口使用同一套词；用户能看懂“下一步做什么”；开发者能从命名直接判断层级和用途。

## 1. 语言策略

| 场景 | 语言 |
|---|---|
| 默认界面 | 简体中文 |
| 英文界面 | `client.js` 的 `en` 字典，与中文 key 一一对应 |
| 代码标识符 | 英文 |
| 代码注释 | 英文，解释“为什么”而不是“做了什么” |
| 用户可见错误 | 中文；必要时附稳定错误码 |
| HTTP action | 英文 kebab-case，例如 `memo-add` |
| HTTP JSON 字段 | camelCase，例如 `sessionRelPaths` |
| Git 提交 | 中文，保留类型前缀 |
| README / docs | 中文；技术名词保留英文原文 |
| 同步值 | `SYNC-<UTC yyyyMMddHHmmss>-<6 digits>` |

原则：

1. **先中文，后英文**：中文是主语言，英文是完整镜像，不是逐字机器翻译。
2. **术语稳定**：同一个概念只使用一个词；不要在同义表达之间来回切换。
3. **动作明确**：按钮写“做什么”，状态写“现在怎样”，错误写“为什么 + 下一步”。
4. **不夸大**：不使用“绝对安全”“完全匿名”“永久免费”等无法保证的表达。
5. **不暴露隐私**：不在界面、日志、提交信息中输出令牌、明文口令、完整绝对路径。

## 2. 核心术语

| 规范用词 | 含义 | 不要使用 |
|---|---|---|
| 多端会话同步助手 | 插件显示名 | 多端同步、会话同步器、Chat Sync |
| 插件 | 本插件 | 软件、工具、应用 |
| 会话 | DSH 的 session 日志 | 对话记录、聊天记录、session 文件 |
| 同步包 | 打包后的 `.dsync` / `.dsync.enc` | 压缩包、数据包、快照文件 |
| 同步值 | `HEAD.revision`，格式 `SYNC-...` | 版本号、revision、哈希值 |
| 公共最新快照 | `users/<user>/common/` | 公共目录、云端最新版 |
| 数据仓库 | 用户自己的 `dsh-chat-sync-data` | 云端、服务器、网盘 |
| 插件仓库 | `dsh-chat-syncer` 源码仓库 | 代码库、Git 仓库 |
| 私有仓库 | 仅账号可读的仓库 | 个人仓库、私仓 |
| 覆盖 | 用选中会话替换公共快照 / 覆盖本机同路径文件 | 全量、强制同步 |
| 增量 | 保留远端其他会话并合并选中会话 / 只补缺失或较新文件 | 差异同步、增量更新（作为模式名时用“增量”） |
| 智能同步 | 连续两次定时无变化后暂停，下次打开或会话完成恢复 | 自动暂停、省电模式 |
| 定时提交 | 按 10 分钟 ~ 24 小时间隔触发 | 定时任务、定时同步 |
| 会话完成提交 | `turn/end` 后 5 秒防抖提交 | 自动提交（容易和定时混淆，正文需带“会话完成”） |
| 检查会话更新 | 读取仓库 HEAD 并比较本机会话 | 检查更新、同步检查 |
| 检查插件更新 | 检查插件版本 | 检查更新（必须带“插件”） |
| 提交最新记录 | 打开会话选择框并推送 | 上传、备份、同步 |
| 下载最近记录 | 拉取仓库最新快照 | 下载、更新、拉取（按钮用“下载最近记录”） |
| 备份与恢复 | 本地覆盖前备份 / 恢复备份 | 回滚、快照恢复 |
| 备忘录 | 按天时间线记录的文字 | 便签、笔记、记事本 |
| 撤回 | 软撤回一条备忘录 / 撤回协议 | 删除（删除是硬删除） |
| 清空插件数据 | 删除本机插件状态、登录、备份、备忘录 | 清空数据（必须带“插件”） |
| 初始化插件 | 恢复默认设置，保留登录 | 重置、恢复出厂 |
| 卸载插件 | 移除本机插件及插件数据，不动聊天和仓库 | 删除、移除 |
| 数据上传协议 | 版本化协议全文 | 用户协议、隐私政策（除非正文确实包含隐私政策） |
| 撤回协议 | 撤回授权并退出登录 | 取消协议、拒绝协议 |
| DSH 本机用户 | 当前操作系统登录用户 | 本地用户、系统用户（正文首次出现可解释） |
| 仓库账号 | 当前 Gitee / GitHub 账号 | Gitee 用户、登录用户（易和 DSH 用户混淆） |
| 设备唯一标识 | 12 位 MAC 或 AUX 指纹 | 设备 ID、设备指纹（fingerprint 是内部字段） |
| 系统版本 | `Windows 10 Pro` 等 | 系统、OS |

### 易混淆词

- “本机”指当前 DSH 所在的电脑；“本地”可以用于“本机数据”“本地备份”，但不要用“本地”指代仓库。
- “仓库”默认指用户的数据仓库；提到源码仓库时必须写“插件仓库”。
- “同步”是总称；“提交”是推送；“下载最近记录”是拉取。按钮不要混用。
- “删除”是硬删除；“撤回”是软撤回；“恢复”是从备份/撤回状态恢复。

## 3. UI 文案

### 3.1 按钮

- 动词 + 对象，2–6 个汉字：
  - 检查会话更新
  - 提交最新记录
  - 下载最近记录
  - 保存
  - 取消
  - 恢复
  - 撤回协议
  - 卸载插件
- 不使用句号、感叹号、箭头符号堆叠。
- 同一动作在不同页面保持同名；不要一处“提交”一处“上传”。
- 破坏性按钮用“危险”样式，且必须二次确认。

### 3.2 状态

使用四类主状态：

```text
已同步
仓库有更新
本机有更新
两边都有更新
```

补充状态：

```text
智能同步已暂停
仓库为空
加密已开启 / 已锁定
协议已记录 / 未签署
正在检查…
正在提交…
```

状态不写“成功/失败”作为唯一信息；要说明对象和下一步。

### 3.3 错误

统一结构：

```text
发生了什么 + 可能原因 + 下一步
```

示例：

```text
当前同步仓库不是私有仓库，已拒绝同步。请先在 Gitee/GitHub 仓库设置中把仓库改为私有，再重试。
```

规则：

- 不责备用户：避免“你错了”“非法操作”。
- 不暴露令牌、绝对路径、仓库凭据。
- 保留稳定错误码，例如 `repo-public`、`remote-ahead`、`encryption-locked`、`memo-empty`。
- 可恢复错误说明下一步；不可恢复错误说明范围。

### 3.4 确认与危险操作

确认弹窗必须包含：

1. 标题：动作 + 对象，例如“清空本机插件数据？”
2. 影响范围：删除什么、保留什么。
3. 不可逆提示。
4. 明确确认按钮；默认焦点在“取消”。

示例：

```text
清空本机插件数据？
删除本机插件存储的登录状态、历史账号、设置、备份和备忘录；
不会删除现有聊天或仓库数据。
[取消] [清空数据]
```

### 3.5 数字、日期、单位

- 文件大小：`1.6 MB`，保留 1 位小数；字节用 `B`。
- 同步值：完整显示 `SYNC-20261109145500-042317`；窄屏可省略中间但 `title` 保留全文。
- 时间：界面使用本地时间，格式 `11/09 15:08`；同步值内部使用 UTC。
- 百分比：`15%`；进度条在等待仓库确认时停在 90%。
- 数量：`{count} 个会话`，不要写 `{count} 个 sessions`。

### 3.6 提示层级

- **非模态 notice**：无更新、轻量结果；20 秒自动关闭，点击空白关闭。
- **toast**：短时成功/失败；4 秒左右。
- **modal**：需要阅读、选择或确认的操作；必须有明确关闭方式。
- **inline warning**：当前页面内的状态提示；不要用来承载必须确认的破坏性操作。

## 4. 代码与命名

### 4.1 JavaScript

- Host 使用 ESM。
- 客户端使用 `React.createElement` 的 `h()`，不引入 JSX 构建链。
- 新增依赖前先确认 DSH 运行时已提供；当前实现尽量零第三方依赖。
- 常量：`UPPER_SNAKE_CASE`，例如 `DEFAULT_REPO_NAME`、`MAX_BUNDLE_BYTES`。
- 函数/变量：`camelCase`。
- React 组件：`PascalCase`。
- 私有字段/方法：不使用 `#`，用命名和模块边界表达。
- 注释：英文；解释边界条件、兼容原因和安全决策。

### 4.2 标识符

| 类型 | 规范 | 示例 |
|---|---|---|
| 插件包名 | 小写 kebab | `dsh-chat-syncer` |
| 插件显示名 | 中文 | `多端会话同步助手` |
| 数据仓库 | 小写 kebab | `dsh-chat-sync-data` |
| 用户目录 | `<provider>-<login>` | `gitee-user_gitee` |
| 设备目录 | `dev-<uuid>` | `dev-b84321e0-...` |
| 同步值 | `SYNC-<UTC 时间>-<6 位数字>` | `SYNC-20261109145500-042317` |
| 包文件名 | `latest-<dataSha256 前 12 位>.<ext>` | `latest-3a16941f36c4.dsync` |
| 错误码 | 小写 kebab | `repo-public` |
| HTTP action | 小写 kebab | `memo-add` |
| JSON 字段 | camelCase | `sessionRelPaths` |
| CSS class | `dcs-` 前缀 + kebab | `dcs-settings-nav` |
| 翻译 key | 点分层级 | `settings.smartDesc` |

### 4.3 API 与数据

- action 名和错误码一旦发布，不随意改名；改名需兼容旧客户端。
- 公开状态不返回令牌、明文口令、绝对路径。
- 仓库路径使用 `/`，本机路径在 Host 内部使用 `path.join`。
- 所有用户可见错误由 `ServiceError`/`ApiError` 携带稳定 code。
- 新增字段优先追加，避免删除旧字段；旧字段保留到下一个大版本。

### 4.4 翻译

- 所有用户可见文本必须走 `tr(key, params)`。
- 同一个 key 同时维护 `zh` 和 `en`。
- key 用英文点分：`account.current`、`status.localAhead`、`memo.clearDesc`。
- 不在 JSX 中硬编码中文；不在模板字符串里拼接用户可见长句（用参数占位）。
- 变量占位统一 `{name}`、`{count}`、`{version}`、`{date}`。

## 5. Git 提交规范

格式：

```text
<类型>: <中文说明>
```

类型：

| 类型 | 用途 |
|---|---|
| `功能` / `feat` | 新功能 |
| `修复` / `fix` | 修复缺陷 |
| `文档` / `docs` | 文档 |
| `维护` / `chore` | 构建、依赖、清理 |
| `重构` / `refactor` | 不改变行为的重构 |
| `测试` / `test` | 测试 |

本项目优先使用中文说明，例如：

```text
功能：增加智能同步暂停
修复：显示检查会话更新结果
文档：重排首页并拆分开发文档
维护：切换许可证为 AGPL-3.0
```

规则：

- 一句话说明“做了什么”，不写“update files”。
- 一个提交只做一件事；文档和代码尽量分开。
- 不在提交信息中写令牌、账号隐私或本机绝对路径。
- 历史英文提交由客户端 `localizeCommitMessage()` 做展示层本地化，不重写 Git 历史。

## 6. 文档规范

- 首页 `README.md`：宣传式概览，不堆实现细节。
- `docs/readme.md`：面向开发者的项目说明。
- `docs/develop-readme.md`：实现、接口、数据格式、流程、测试、发布。
- `develop/`：开发入口和本规范。
- 新功能至少更新：项目说明、开发文档、必要的 README 首页亮点。
- 截图放在 `docs/`，文件名使用小写 kebab：`settings.png`、`memo.png`。
- 文档中的路径、仓库名、同步值必须与代码一致。

## 7. 安全与法律措辞

- 使用“私有仓库”“仅账号可读”，不使用“绝对安全”。
- 说明“Git 历史不会自动清理”，不要让用户误以为删除最新文件就删除历史。
- 说明“恢复文件在私有仓库内”，不要承诺作者可以帮用户找回。
- 许可证统一写 `AGPL-3.0-only`。
- 不在界面中自动附加“本协议不构成法律意见”等免责声明；如产品需要，必须单独评审。
- 作者信息统一为 `XAF`。
